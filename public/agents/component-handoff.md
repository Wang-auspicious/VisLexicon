# 素材采集、检索与卡片展示规范

定稿：2026-09-21。面向接手批量工作的 Agent。先完整阅读本文件，再读 [组件采集协议](./component-capture.md) 和 [34 组填空表](./component-questionnaire.json)。本文件固定展示方式和新增的栏目、来源、费用要求；填空表负责逐实例的证据门禁。不要重新设计页面。

## 你要交付什么

一次交付一个真正完成的组件实例，而不是一句网站介绍或一个仓库链接。一个站有 200 个组件，就逐个进入组件详情；10 个外观不同的 button 要形成 10 个可区分的实例。默认、悬停、按下等是同一实例的状态，不算 10 个新组件。相同外观出现在两个网站，可以关联两个来源，但原始观察各自保留，不能删除其中一次采集。

每个实例需要：明确定位、真实截图、数值和样式、逐状态行为、动画机制、响应范围、中英文描述、重建 prompt、检索标签，以及与当前内容摘要绑定的独立复核。看不清的参数应继续测量；视觉估算必须逐值写依据和区间。没有证据的行为、授权、费用和源码条件不能估算。

## 执行节奏：像做填空题

1. 在 frontend 执行 `npm run capture:init -- 稳定的英文小写实例ID`，生成私有草稿。不要覆盖已有记录。
2. 执行 `npm run capture:next -- data/discovery/captures/实例ID.json`。每次只回答返回的最多 5 个问题。
3. 打开实际页面，定位当前实例；截图、读取 DOM / 计算样式、操作状态，保存原始证据后再填写答案。不要凭组件名或示例文案推测实现。
4. 运行 `npm run capture:check -- data/discovery/captures/实例ID.json`，修正当前错误，再领取下一组。
5. 34 组完成后交给独立复核者。复核者不能等于采集者，批准必须绑定当前内容摘要；改了答案、证据或预览就重新审。
6. 只用 `npm run capture:publish` 发布完整记录，然后 `npm run discovery:build` 刷新栏目索引。有新的原网站关联时，还要通过下文的关系复核与发布门禁。
7. 运行 `npm run capture:verify`、相关测试与构建，在浏览器实际搜索并打开结果。确认当前实例的动画、标签、正文和原网站链接都正确后，再开始下一项。

不要在一个回合里给自己几十个未答问题。任务中断时记录当前实例 ID、已答组、未答组、最后一份证据和下一步；恢复后先读草稿并运行 `capture:next`，不能靠记忆补答案。

## 采集覆盖与原始账本

- 先列网站的真实导航、类别、详情页、分页、加载更多和示例入口。每页有 visited / pending / blocked 状态及原因。未翻完不能说“已完整抓取”。
- 原始观察先保存，再分类或去重；原始命中总数必须等于各处置状态数量之和。
- 当前实例在 inventory.observations 中必须有明确的 `indexed-instance` 处置与实例映射；其余逐项标 `pending-detail`、带证据的 `classified-noncomponent` / `component-fragment`、重复对应关系或阻塞原因。原始命中一条不漏。
- 动态 DOM class 可能把 `fxoff` 这样的状态串混入原始 ID。保持原始 ID 不变，另写到稳定实例 ID 的映射，不要偷偷清洗历史证据。
- 仅名称、logo 或同域名不能证明两个入口是同一实体；保存合并、拆分依据。

## 每个实例必须回答的内容

以下是问题范围提醒，正式字段以填空表为准，不能以这段摘要代替完整作答。

- **身份与范围**：原网站、最终 URL、具体示例锚点、定位器、系列、变体、主题、视口、DPR、缩放和采集时间；本次究竟核验到哪里。
- **结构**：每一层是什么、前后顺序、父子关系、数量、对齐方式、占位内容与实际内容的区别。
- **尺寸与布局**：组件宽高、内外距、间距、边框宽、每角圆角、内容比例、对齐、定位、换行、溢出和尺寸约束。数值带 px / % / rem 等单位。
- **色彩与质感**：背景、文字、边框、各层透明度；渐变角度与每个 stop；阴影每一层的 x / y / blur / spread / color / inset；模糊、蒙版、裁切等。
- **文字与图标**：实际文案、字体来源、字号、字重、行高、字距、对齐；图标来源、笔画、大小和间隔。没有文字也要明确回答，不拿占位短线当文字。
- **状态**：默认、hover、focus、pressed、disabled、loading、selected、反馈；逐一核验或给出有源码/DOM依据的“不适用”。“没试”不能写“不适用”。
- **运动**：触发条件、运动目标、属性、起止值、单位、duration、delay、easing、iteration、direction、stagger、退出与中断行为。确认是否真的跟随鼠标坐标，还是固定角度的 hover。
- **响应与辅助功能**：至少两个实际 CSS 视口；换行和溢出；减少动态、触屏、键盘和可访问语义分别记录证据方法，不能把 iframe 当真机测试。
- **区分与检索**：与最近似实例有哪些可观察差异；至少 3 条自然语言正例与 2 条应排除的反例；对象、结构、形状、颜色、材质、排版、运动、触发、场景九轴标签。

## 描述与反推 prompt

正文只写一次，不再加一个复述同样内容的摘要或折叠说明。用固定段首组织文字：

> 结构：对象、组成与前后关系。
>
> 尺寸与布局：宽高、边框、圆角、内外距、比例与对齐。
>
> 色彩与质感：具体色号、透明度、阴影和渐变。
>
> 字体与图标：只有实际存在时才写公开段落；填空表仍必须回答。
>
> 运动与状态：实际触发和变化参数；静态就写实测静态。
>
> 响应与范围：测试视口、尺寸变化、溢出与适用边界。

旧范例的“尺寸 / 色彩与层次 / 交互 / 响应”也能被前台分段。不要发明新的装饰性标题导致整篇无法解析。英文内容必须与中文同事实，可用 Structure / Size and layout / Color and material / Typography / Motion and states / Responsive scope。

重建 prompt 留在结构化记录中：说明要做什么对象，按层写构图和尺寸，列出颜色与字体、状态与动画、响应约束、禁止出现的近似效果，最后给出能观察验证的验收标准。不是写“做得高级一点”“有科技感”就结束。不要把原站没实现的建议写成实际效果。

## 已确认的卡片展示规范：后续不得自行改版

| 元素 | 固定要求 |
| --- | --- |
| 名称 | 16px，比上一版 14px 增大 2px；字重 650；使用 Anthropic Sans 的英文字形和现有中文回退字体。 |
| 小标签 | 紧接名称之后，最多 3 个简短代表标签；12px、圆角胶囊、浅色底，不加下划线。窄卡片放不下时自然换行，不能遮盖保留按钮。 |
| 标签颜色 | 对象/结构用浅青底蓝字；形状/材质/运动等风格标签用浅紫底紫字。技术和许可若展示，沿用全站绿色和米黄色 token。颜色只表达类别，不表达未取得的审核状态。 |
| 段首标签 | 14px，比上一版 12px 增大 2px，字重 650；“尺寸：”等与正文同一行。不能单独占一行。 |
| 正文 | 13px，清晰的段间距；每个事实只出现一次。尺寸保留精度依据，不机械展示过多小数。 |
| 色号 | 每个合法 #RGB / #RGBA / #RRGGBB / #RRGGBBAA 后紧跟该颜色的小色块；白色也要有边框。文字仍可复制。 |
| 预览 | CSS/SVG/交互动画保留原机制；不能用截图冒充动画、用统一悬浮动效替换原效果、擅自加速。静态实例保持静态。 |
| 来源 | 描述下显示来源图标 + 名称，直接到原网站具体实例；多个已核实来源可并列列出。不得要求用户先跳去策展。 |
| 费用和代码 | 显示明确的免费范围、源码入口和许可来源；免费核心库与付费模板必须区分。 |
| 隐藏信息 | identity / breadth / proof、文件路径、内部 ID、复核报告留后台；不放右上箭头，不在底部重复标签。 |

数字统一是 CSS px。不要按截屏的放大倍率把 16px 标题误改成 32px。预览本身的原站字体和图形是证据内容，不为统一网站界面字体而悄悄改写已经复核的预览文件。

## 各栏目独立检索

策展、图鉴、Skill、PPT、科研绘图分别有自己的候选集。主题筛选继续限定当前栏目的子集。请求必须包含 scope，必要时包含 theme；缓存、查询、保留结果和响应验证均按栏目与主题隔离。不能为了填满某栏，从其他栏目取结果。

策展里的现有网站介绍只能证明网站层面的内容，不能当成这个网站所有组件都已逐状态测过。图鉴的精细组件索引只接收经过采集复核的实例；旧公开创作研究保持自己的记录类型，不能冒充 v2 组件采集。原来的 112 条试验组件仍在私有档案中，不能直接搬回检索。

不要承诺“全部 8000 个网站都完成了”。当前已完成多少网站层索引、多少独立实例、多少原始观察仍待深入，要分开统计。

## 图鉴到多个原网站的关系

一个图鉴实例可关联多个网站的具体实例。每条关系要有站点 entryId、原网站 URL / 锚点、匹配级别、中文与英文差异说明、DOM / 原站源码和截图证据、采集时间，以及原始观察处置。

- `same-pattern`：同一种可观察实现模式，仍明确写尺寸、色彩、速度差异，不能声称像素完全相同。
- `related-variant`：相近变体，例如固定双色旋转圆环与弧长变化的 SVG 蒙版。公开说明区别，不能冒充同一个实例。
- 仅“这个库有 Button”不能证明它有当前风格的 Button；名称映射、图标相似、通用卡片标签不构成关系证据。
- 没有找到匹配的网站，就保留未关联状态；不乱补首页链接。

关系草稿在 `data/discovery/source-relations.json`，原始材料在私有 raw 目录。执行 `scripts/discovery-relations.mjs` 的校验和发布流程；独立复核报告需要明确 approved、不同的 reviewer、当前 contentDigest、至少 3 条实际检查和报告文件哈希。只发布指向已发布采集实例的关系。公共关系不能与审核版本漂移。

## 免费、源码和授权：必须属于同一份资源

逐个资源填清：哪一份内容、是否免费访问、是否有源码、源码获取费用、源码链接、许可证及原文链接、许可覆盖范围、商业使用条件、核验日期和直接证据。

- “免费浏览”不能推导“下载源码免费”；“有 GitHub 链接”不能推导“开源”；“MIT 的核心包”不能覆盖同站商店模板。
- “免费且有源码”要由同一份 offer 同时满足，不能拿 A 页免费和 B 页付费源码拼成满足。
- “源码可以收费，免费浏览即可”必须按这两个独立条件理解；“不免费也可以”不能被强行当作免费要求。
- “免费预览，源码 $49”不能标成免费源码。“未见付费墙”不能因含“付费”两个字而变成部分收费。
- 没有证据就 unknown，不能进入要求该条件的肯定结果；缺少许可证不等于禁止使用，也不等于可商用。
- 现有已审网站事实由 `build-discovery-scopes.mjs` 保守投影。事实相互矛盾、有价格归属歧义或超过核验周期时，退回待核验，不靠模型猜测。新采集优先填写清晰结构化 offer，避免继续依赖长段价格文案。

## 已遇到的坑

1. 把内层卡片也设成 flex 演示台，会把 177px 高的卡片压塌到几十像素。舞台居中容器与组件自身布局分开，复核真实 DOM 宽高。
2. CSS 文案可能写“跟随鼠标”，实际代码只是 hover 固定倾斜。必须移动指针检查是否随坐标改变。
3. 动画不一定出现在 computed animation：daisyUI 的圆环是 SVG mask 内部 SMIL。读实际 SVG 属性和可见变化，不能因为 animation:none 就判静态。
4. 旋转元素的 getBoundingClientRect 是轴对齐外包框，不是原直径。52px 圆环在旋转时父方框的 bbox 可达约 73.5px；记录布局尺寸与变换后 bbox 两者。
5. 连续三张自然截图是采样窗口的首、中、末，不能自称精确 0% / 50% / 100% 动画关键帧。记录时间和真实相位；若要一整周期，用足够覆盖周期的采样。
6. 浏览器视口接口有时不实际改变 innerWidth；以实测为准。390px iframe 可以验证 CSS 窄布局，但不是触屏设备。
7. 相邻垂直 margin 可能折叠，14px 与 9px 不能未经测量就加成 23px。
8. 截图文件叫 .png 不保证字节是 PNG；使用真实解码器验证。伪造 PNG 文件头不能过审核。
9. 重型网页不要反复读取整页 AX；定位后读取局部 DOM。操作超时记录为失败，不冒充成功；换方法后说明新证据能证明的边界。
10. 字体文件可下载不等于它是开源授权。Anthropic Sans 的官方来源记录在 `/fonts/anthropic-sans-source.json`；不要给它自动贴“免费可商用”标签。

## 完成前逐项自问

- 我能从原始入口再次定位到这个具体实例吗？
- 所有数字都来自实测、源码，或有逐值范围和依据的估算吗？
- 动效预览真在变化吗？减少动态偏好和已核验的原机制是否保留？
- 标签与描述能把它和最相近的变体区分开吗？
- 免费、源码和许可是否指向同一个具体资源，而非网站品牌的泛泛介绍？
- 标题后的胶囊标签、行内加粗段首、色号色块和原网站直达链接是否符合定稿？
- 原始观察数守恒、当前实例处置正确、独立复核摘要有效了吗？
- 在正确栏目输入正例和反例后，结果、费用条件和主题隔离是否实际正确？

只有全部满足，才将这个实例标为完成。未完成项进入私有待补全队列，留下具体下一步。
