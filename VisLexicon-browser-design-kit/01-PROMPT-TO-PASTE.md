# 上传后发给设计模型的提示词

你现在接手 VisLexicon（视元）的产品与网页设计。请先完整阅读根目录的 `00-READ-ME-FIRST.md`，然后按其中顺序查看 `context/`、`current-ui-screenshots/`、`content-samples/` 和 `frontend/src/`。

这不是一次只换颜色和圆角的美化任务。请重新判断整站信息架构、内容优先级、桌面与移动端用户路径，以及“策展”和“图鉴”如何互相导流。本轮明确授权重新设计布局；当前截图只代表现状，不是必须保留的方案。

设计时必须使用代码库中的真实内容样本，不得虚构网站、术语、统计、截图或来源。严格区分候选内容与已审核内容；网站详情必须能够表达身份、内容范围、事实证明、三张截图及直接来源。样本数据的 12 和 220 不是生产总量，正式规模以 `00-READ-ME-FIRST.md` 为准。

请分四步交付：

1. 用简洁语言复述你理解的产品、核心用户、当前结构和最严重的设计问题。
2. 给出新的信息架构、导航、关键任务路径及内容模块，明确哪些保留、合并、移动或删除。
3. 给出桌面与手机的关键页面方案，包括策展首页、目录/详情、图鉴舞台、术语详情和提交入口；描述重要状态与交互，不要只给静态首屏。
4. 在方案获得确认后，再基于 `frontend/` 生成可运行实现，并逐项说明改动文件。

视觉上应有明确而统一的编辑气质，但不能让装饰压过检索、理解、比较和证据阅读。先做判断，再做界面。
