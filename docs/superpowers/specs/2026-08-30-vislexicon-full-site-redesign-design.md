# VisLexicon 全站成品化与 Oreo 策展复刻设计规格

**日期：** 2026-08-30  
**状态：** 已确认，进入实施  
**事实基线：** `Claude-最新完整对话整理.md`

## 1. 产品目标

VisLexicon 同时服务人类设计选型与 Agent 设计上下文供给。首页默认进入“策展”，但全站不是一个 Oreo 风格的组件站：

- **策展**解决“在 1.5 秒内判断一个外部设计站是否值得打开”。
- **词典**保留五轴视觉词表、词条图鉴、变体矩阵与二叉检索的知识结构。
- **工具**是专业测量工作台，结果必须可复现、名实相符。
- **提交**是可验证的社区贡献入口；没有后端时不得伪称已进入真实审核队列。

## 2. 视觉边界

### 2.1 全站顶栏

只学习 Oreo 的简约与克制，不复制其业务内容：

- 桌面高度 `80px`，左右内距 `36px`。
- 品牌字号 `16px/600`，导航 `14px/400`。
- 纯文字主导航，当前项只用字重/颜色变化，不用厚重胶囊和滑动底块。
- 搜索、主题和 Spec 板保留为轻量图标/文字动作，不与主导航争抢层级。
- 手机端允许换为紧凑两行布局，但主频道必须始终可达。

### 2.2 策展频道：Oreo 复刻区

Oreo 视觉语言只出现在外部网站展示区。以 1280px 视口的官网实测值为桌面基准：

- 页面与卡片底色：`#f9f9f8`。
- 白色展示底板：约 `1174px` 宽、`32px` 圆角、`8px` 内距。
- 三列网格：列间距 `9px`、行间距 `8px`。
- 卡片：基准 `380 × 330px`、`24px` 圆角、`1px solid #e4e4e4`。
- Hover：`0 8px 32px rgba(0,0,0,.08)`，不做夸张位移。
- 截图区占卡片主要篇幅，使用一大两小的三联真实截图。
- “画面到头”使用定向渐隐覆盖：右侧宽约 `149px`，透明至底色 `69%`；底部高约 `171px`，透明至底色 `50%`。

每张卡片必须遵守：

1. 三张截图都来自该卡对应源站，且画面不同、能代表不同能力。
2. 整卡是一个外链，直接在新标签页打开源站。
3. 底部严格三行：
   - 名称 / 体量 / 价格；
   - 浅紫技术栈标签；
   - 浅绿主题标签单行无缝循环，左右渐隐。
4. 禁止作者大介绍、雷达评分、源站按钮、装饰符号、长文案和额外操作按钮。
5. `prefers-reduced-motion` 下停止自动滚动，并保证标签仍可横向查看。

筛选采用“用途一级分类 + 技术栈二级筛选 + 全文搜索”的简化组合方案。手机端变成单列，平板双列，所有尺寸不得横向溢出。

### 2.3 其他频道

- **词典**使用编辑型目录、轴线、术语层级和可运行样本，不套用策展卡片。
- **词条/解剖台**使用参数面板、时间读数、关键帧和代码/结构说明；不同词条显示与自身属性相关的数据。
- **工具**使用工作台布局、输入区、结果图、数据表和可复制指令，强调准确性而非营销感。
- **提交**使用表单和本地草稿/导出状态，清楚说明当前是否真的发往服务端。

## 3. 数据与真实性

策展数据从 JSX 中拆到独立模块。每条上线记录至少包含：

```js
{
  id, name, site, scale, pricing,
  stacks: [], themes: [], category,
  shots: [
    { src, sourceUrl, alt },
    { src, sourceUrl, alt },
    { src, sourceUrl, alt }
  ]
}
```

发布校验必须拒绝：重复 `id`、非 HTTPS 源站、截图不足三张、同卡重复图片、跨站图片路径、缺失来源 URL、空技术栈/主题标签。1087 条候选只作为待清洗数据，不可未经核验直接倾倒进成品。

首批以 12 个已确认站点为上限；若某站无法取得三张可追溯截图，则暂不展示，不使用别站图片顶替。

## 4. 功能诚实性与专业修复

- Store 加载后必须立即生成新 snapshot；刷新时主题、Spec 数量与本地存储一致。
- “加入 Spec”与“更新参数”分离；再次保存已入板词条时更新参数，不意外删除。
- Spec 的“交给 Agent”只有在存在真实端点时才可发送；否则提供复制/下载，不伪造网络成功。
- Palette 零结果不可 `% 0`，并提供 `dialog`、焦点恢复、键盘循环与 Escape 语义。
- Diff 不再把 RGB 欧氏距离称为 ΔE；实现标准 Lab 转换和 CIEDE2000，输出真实网格热图。
- `hotCells.slice(0, 5)` 必须逐项展开，不得产生嵌套数组崩溃。
- Lexicon 不显示 `undefined` 家族名；未知家族有明确后备文本。
- Variants 将当前词条传入 `self`，格子可进入对应词条；Compare 的每列参数状态独立，差异说明来自实际参数差。
- 生成端点使用派生路径 `/lexicon/{id}.json`，`llms*.txt` 禁止出现 `undefined`。
- Submit 无服务端时只保存本地草稿并允许下载 JSON，文案明确“尚未发送”。

## 5. 无障碍与性能

- 所有交互元素有可见 `:focus-visible`。
- 弹层具备 `role="dialog"`、`aria-modal`、可读标题、首焦点和关闭后的焦点恢复。
- 纯装饰动画在 `prefers-reduced-motion` 下关闭。
- 图片 `loading="lazy"`、`decoding="async"`，显式宽高/比例防止布局跳动。
- 390px、768px、1280px 三个验收视口无横向滚动条。
- 外链包含 `target="_blank" rel="noopener noreferrer"`，截图 alt 描述具体画面而不是只写“截图”。

## 6. 验收证据

完成不能靠口头声明，必须同时提供：

1. 数据校验、筛选、Store、色差和端点测试的实际输出。
2. `npm run lint` 与 `npm run build` 的最新成功输出。
3. 1280 / 768 / 390px 本地页面截图。
4. 1280px 策展区与 Oreo 官网参考的尺寸/颜色/间距对照记录。
5. 对每个上线站点的三张截图来源清单；无法核验的条目必须下线而非占位。

## 7. 实施约束

- 根目录当前不是 Git 仓库，不能创建 worktree 或提交设计 commit；所有改动在现有工作区完成并保留可审查文件差异。
- 先恢复完整 CSS 历史快照，再以附加覆盖区重写顶栏和 `.oreo-*`，避免再次丢失词典、工具与提交样式。
- 不引入无必要的大型 UI 框架；沿用 React 19、Vite 和原生 CSS。
